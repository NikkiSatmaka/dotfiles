## Shell setup

Zsh initializes fzf, mise, and zoxide through their Oh My Zsh plugins. Keep
their `shell-tools` initializers for Bash and Fish only. Zephyr owns completion
initialization and caching; it loads before plugins that call `compdef`.
Powerlevel10k uses its explicit theme entry point.

Zsh command completions are generated by `shell/refresh-completions.sh` after
chezmoi installs/changes the generator and after mise installs tools. Docker,
kubectl, Podman, and uv aliases/functions are retained in `shell/alias.d/cli-aliases.zsh`
with the upstream MIT notice, without their per-start completion generators.
Zsh loads `shell/alias.d/*.zsh` after its completion framework is available;
Bash and Fish do not source these Zsh-specific files.
The alias snapshot must be updated explicitly when adopting upstream alias
changes. Startup loads completions from cache, so compinit's cache stays valid.

OMP's Bash and Zsh initializers use the shared `cache_command_output` helper,
independent of z1's `cached-eval` interface. A missing/stale cache is generated
once; subsequent starts reuse it. Generation failures preserve the last good
file. Fish autoloads OMP completions on the first completion request. Dynamic
completion requests still invoke OMP when needed.

After upgrading tools outside mise, refresh completions explicitly and open
a new shell:

```sh
sh "${XDG_CONFIG_HOME:-$HOME/.config}/shell/refresh-completions.sh"
```

`STARSHIP_CONFIG` and `NPM_CONFIG_USERCONFIG` are exported by `30-tools.sh`.
The managed npmrc uses npm's `${VARIABLE}` syntax; XDG defaults come from the
shared environment. PowerShell points Starship at the same `.config` layout.

Use `copy_output command [arguments...]` to copy a command's stdout, for
example `copy_output git status --short`. For pipelines, pass an explicit
shell command, such as `copy_output sh -c 'printf hello | tr a-z A-Z'`.
Failed commands preserve their exit status and do not replace the clipboard.
Rclone wrappers preserve transfer failures, quote paths, and pause only when
stdin is a terminal.

`ssource` skips unreadable or missing optional files, but preserves diagnostics
and exit status when an existing file fails. Source required files directly.

Fish imports shared environment exports through a POSIX shell subprocess with
NUL-delimited output. Login shells also import `login.sh`. Fish aliases and
functions belong in native `.fish` files; POSIX `.sh` files are never sourced
directly by Fish. Tool integrations run only in interactive sessions.

tmux explicitly uses Zsh independently of the account's login shell. Chezmoi
renders its path at apply time, preferring Homebrew Zsh: `/opt/homebrew/bin/zsh`
then `/usr/local/bin/zsh` on macOS; `/home/linuxbrew/.linuxbrew/bin/zsh` then
`~/.linuxbrew/bin/zsh` on Linux. If neither exists, it uses `/bin/zsh`.
Homebrew's Zsh can remain installed as an Antidote dependency; it does not need
to become the login shell. The main tmux config is symlinked to the source, so edits are available immediately;
reload it with Prefix r in tmux. Only `~/.config/tmux/shell.conf` is rendered by
chezmoi; reapply that file after changing its template or installing/removing Zsh:

```sh
chezmoi apply ~/.config/tmux/tmux.conf ~/.config/tmux/shell.conf
```

Apply both paths once when migrating from the rendered main config. Subsequent
ordinary tmux config edits only need a reload; shell changes need an apply first.

Preview and apply just the shell configuration, without bootstrap scripts or
external repository updates:

```sh
chezmoi apply --dry-run --verbose --exclude=scripts,externals ~/.config/shell ~/.config/zsh ~/.config/fish
chezmoi apply --exclude=scripts,externals ~/.config/shell ~/.config/zsh ~/.config/fish
```

`.chezmoiremove` removes the retired initializers on apply, including copies
left behind on other devices. Open a new terminal after applying.

Run the shell regression checks with:

```sh
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -v
```
